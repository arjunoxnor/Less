## Headline

The project does **not** need a rebuild. The architecture is sound, the build is
clean, and most of what the critics found is fixable in place. The sync layer is
the one subsystem sitting near the rewrite line, and it should be refactored and
given tests rather than torn down.

But the single most important finding is a correction to something I told you was
already fixed:

> **The cross-device title/status clobber is NOT actually closed (F1, F41,
> confirmed high-confidence by two independent lenses).** The per-field clocks
> (`title_at`, `status_at`) I added protect the *timestamp*, but the content
> autosave still sends the title *value* on every keystroke-driven save. So the
> common case, a script open on one device while you rename it on another, still
> silently reverts the rename. The dedicated clock is defeated because the title
> rides out on the content path.

I previously described this class as "structurally impossible." That was wrong.
It is the first thing Opus should fix, and it is a small change (stop sending
`title` on the content PATCH).

## The rebuild question, answered

Two findings argued toward large-scale change; both were held below rebuild:

- **F44: `reconcile()` is a 260-line function mixing five sync domains.** Real,
  and it is exactly where the past regressions have lived. But the fix is to
  carve it into named, independently testable steps (push-anonymous, folders,
  pull-new, title/status, placement, tombstones), not to redesign the sync
  model. The per-field-clock model is correct; it just needs seams and tests.
- **F43: `ScreenplayBody` and `PlainBody` duplicate ~180 lines of save and
  lifecycle wiring.** Extract a shared hook, do not merge the two editors.

The local-first + per-field-clock design is the right design. The problem is not
the model, it is that the model is implemented in one giant untested function and
partly bypassed by the content-save path (F1). Fix those two things and the whole
class of "org glitched again" bugs closes for real.

## Tier 1: data-loss and correctness, fix first (small, high impact)

These are cheap and directly protect a writer's words. Do them before anything
else.

1. **F1 / F41: content autosave clobbers a newer remote rename.** In
   `lib/cloud/scripts.ts` `saveScript`, drop `title` from the PATCH body so the
   content path is content-only. Renames already flow through `setScriptTitle`
   (title-only, own clock, own dirty flag). Update the three callers in
   `useCloudSync` (`pushNow` ~127, reconcile push ~196, `flushBeacon` ~359/367)
   to pass content (+ optional title_page) only. For auto-named plain docs, route
   the derived title through `setScriptTitle` behind a value-changed check.
   Verify with a two-session test: rename on A while B has it open and typing.

2. **F4: sign-out drops unsaved edits.** Sign-out runs from inside the open
   editor and immediately calls `dropCloudProjects()`, but the 1.5s debounced
   push may still hold edits. `await` a synchronous flush of the current
   document before clearing cloud-derived local state in the `useProjects`
   identity-transition effect.

3. **F11: `dual` and `note` attributes leak onto new lines.** On Enter/split and
   on element change, the new line inherits `dual` and `note`, producing phantom
   gutter notes and mis-indented lines. In `lib/editor/keymap.ts` (the split
   handler) explicitly reset `dual`/`note` to defaults on the created line.

4. **F10: AutoCaps aborts IME composition.** `AutoCaps` rewrites the text node
   mid-composition, which cancels CJK/accented input. Guard the
   `appendTransaction` in `lib/editor/autoCaps.ts` to no-op while
   `view.composing` is true (and re-run once on `compositionend`). Same guard
   belongs on `SmartCaps` input rules.

5. **F18: Fountain export does not escape leading special characters.** A line
   starting with `.`, `!`, `@`, `~`, `>` etc. is reserved Fountain syntax; on
   re-import it silently reclassifies (an action line becomes a forced scene
   heading, dialogue becomes lyrics). In `lib/export/fountain.ts`, escape leading
   force-characters on action/dialogue/character text. Add a round-trip test
   (export then import, assert element types preserved).

6. **F5: localStorage quota errors are swallowed for cloud bookkeeping and
   folder writes.** `lib/storage/localStore.ts` `set` returns false on quota
   failure, but folder writes and cloud-bookkeeping writes ignore the boolean.
   Propagate it and surface the existing "storage full" status the editor
   already has, so a full device does not silently corrupt sync state.

## Tier 2: substantial fixes (a focused work session each)

7. **F16 + F17: two pagination engines that disagree.** The on-screen page
   sheets (`lib/editor/pagination.ts`, DOM measurement) and the printed PDF plus
   status-bar count (`lib/export/paginate.ts`, layout model) are entirely
   separate and diverge on every hard case (long speeches, cue-at-boundary,
   dual dialogue). A writer sees 3 pages on screen, exports 4. Decide on one
   source of truth. Recommended: keep the DOM engine for the live view, and make
   the status-bar count read from the same engine (`pages` it already computes)
   instead of re-running the export paginator (F37). Longer term, converge the
   PDF engine's break rules onto the same rule table so export matches screen.
   This is the biggest correctness item and deserves its own session.

8. **F2: no cross-tab coordination.** Two tabs on one device (or dashboard +
   editor) silently diverge and the last writer clobbers. Add a `storage` /
   `BroadcastChannel` listener at the storage layer: on a sibling-tab write to
   this project's doc key, pull into the editor if clean, or show a conflict
   indicator if dirty. This is the same "lost writing on one machine" class the
   local-first promise is supposed to make impossible.

9. **F25 + F26 + F27: API hardening (security).** All three confirmed high.
   - F27: cap request body size on write endpoints in
     `functions/api/[[path]].ts` (reject oversized content before touching D1).
     Cheapest and highest value; do first.
   - F26: add basic rate limiting (per-IP or per-identity) to `auth/google`,
     `auth/claim`, and write routes. Cloudflare has native options.
   - F25: the claim endpoint re-owns data with no throttle, so a leaked sync
     code silently transfers a writer's whole library. Rate-limit claims and
     consider requiring confirmation before a claim moves existing rows.

10. **F34: reconcile is an N+1 serial round-trip storm.** Signing in with 50
    projects fires ~50 sequential awaited network calls. Batch or parallelize
    (bounded concurrency) the per-project and per-folder pushes. Pairs naturally
    with the F44 refactor.

11. **F32 + F33: editor typing-path cost.** Every keystroke calls
    `editor.getJSON()` twice plus `getText()` once (full-document
    serialization), and the pagination `ResizeObserver` on `view.dom`
    re-triggers its own measure loop when its spacers change height. Debounce and
    de-duplicate the serialization; make the ResizeObserver ignore
    spacer-induced resizes. Feature-length scripts will thank you.

12. **F35: unbounded localStorage growth.** Every project keeps full doc, title
    page, page lock, and breakdown locally forever with no eviction. On a heavy
    user this eventually hits QuotaExceeded and silently blocks saves. Add an
    eviction policy for cloud-backed docs (keep the index, lazy-load bodies;
    evict least-recently-opened bodies that are known-synced).

## Tier 3: architecture and the test gap (do alongside Tier 2)

13. **F42: zero automated tests on a sync layer with a regression history.**
    This is the meta-fix. A tiny test harness around the reconcile decision
    logic (given local meta + cloud row + clocks, assert which side wins and what
    gets pushed) would have caught F1 immediately. Add unit tests for: title/
    status/placement conflict resolution, tombstone flushing, the claim re-key,
    and quota-failure paths. Do this *before or during* the F44 refactor so the
    refactor is safe.

14. **F44: refactor `reconcile()` into named steps.** Once tests exist, split the
    god-function into independently testable stages. No behavior change; pure
    structure. This is what moves the subsystem back from the rewrite line.

15. **F43: extract the shared editor shell** used by both `ScreenplayBody` and
    `PlainBody` into one hook, so save/lifecycle/sync wiring stops drifting
    between the two copies.

16. **F48: introduce a single project facade** so components stop calling storage
    and cloud orchestration directly. Optional but supports the above.

## Tier 4: product and UX (a writer's first impression)

The unimpressed-pro lens landed three confirmed substantial items worth a
product conversation, not just a code fix:

- **F50: no mobile or tablet layout.** The editor is a fixed 8.5in slab that
  forces horizontal scrolling on any narrow screen. At minimum, make the
  dashboard and reading view responsive even if editing stays desktop-first.
- **F51 + F55: the keyboard-driven workflow is undiscoverable.** A first-timer
  gets a blank cursor with no hint that Tab cycles elements, Enter flows, etc.
  Add a quiet first-run hint or a sample script. This is high-leverage for the
  "simple, fast" pitch.
- **F52: local-first writers get no rollback.** Version history is cloud-only, so
  the pitch's core user (no account) has no safety net. Consider a small local
  snapshot ring.

And two stale-docs items that are pure cleanup but embarrassing if anyone reads
them:

- **F53: README** still says "Phase 1 in progress", Vercel, and Supabase for an
  app that is fully built and live on Cloudflare.
- **F54: the zArchive one-pager (`Less.md`)** still documents Supabase + Vercel
  as the live stack. Update to Cloudflare D1 + Pages + Google/sync-code auth.

## What did not survive verification (recorded so it is not re-litigated)

- **F3 (refuted -> qol):** the "reconcile pull discards in-progress edits" race
  is guarded by the existing `typedDuringFetch` snapshot; the residual window is
  a narrow qol hardening, not a live data-loss path.
- **F49 (refuted -> qol):** duplicate of F16/F17; the disagreement is real but

- **F12, F31, F36 (downgraded -> qol):** the pagination re-measure, the
  CONT'D/breakdown decoration rebuilds, and the autocomplete candidate rebuild
  are real inefficiencies but perform acceptably at current scale; fold them into
  the Tier 2 performance work rather than treating them as separate bugs. Note
  F32/F33/F34/F35 (the ones that survived at substantial) are the performance
  items that actually bite.

## Implemented in this run

Shipped on `superaudit/2026-07-01` across seven commits. All gated on `tsc`,
`next build`, and `npm test`.

**Data-loss / correctness (Tier 1)**
- F1/F41: content autosave no longer carries the title. `saveScript` is
  content-only, the API ignores `title`/`status` on any PATCH that has
  `content`, and a real local title change (rename or plain-doc auto-name, via
  `titleDirty`) is pushed through the title-only endpoint. The cross-device
  rename clobber is closed for open editors.
- F4: signing out from inside an editor awaits a flush first.
- F5: a full/blocked localStorage broadcasts `less:storagefull`; a sticky
  `StorageBanner` surfaces it.
- F10: AutoCaps no-ops during IME composition.
- F11: Enter-split no longer inherits a per-line note or leaks the dual flag.
- F18: Fountain export forces `!` on action lines that would re-import wrong.

**Security**
- F27 body cap (3MB), F30 malformed-JSON 400 + generic 500, F28 JWKS cache,
  F29 session-JWT alg pin. F25/F26: best-effort per-IP throttle on
  auth/google + auth/claim (per-isolate; a durable KV/Durable-Object limiter is
  the real fix, still open).

**Pagination / perf**
- F17/F37: status bar and reports read the visual engine's page count (one
  source, no per-keystroke export recompute). F33: one fewer full `getJSON` per
  keystroke. F32: pagination ResizeObserver recomputes on width changes only.

**Sync architecture / tests**
- F42: vitest added; `lib/storage/lww.ts` holds the pure LWW decision logic with
  14 tests pinning the rename/status/placement rules (incl. the F1 case).
- F44: reconcile now calls `decideField`/`decidePlacement` (tested seam).
- F34: first-sign-in project push and tombstone flush use bounded concurrency.
- F2: cross-tab BroadcastChannel; an idle tab adopts a sibling's newer save.

**Product**

  hints.
