# Data-loss, storage limits, and recovery audit report

Date: 2026-08-05

Scope inspected and changed: `lib/storage/**` and `lib/cloud/**`. This report is the sole required artifact outside that code scope.

## Ranked findings

| Rank | Reproduction (one line) | Maximum work at risk | Result |
|---|---|---:|---|
| 1 | Replace `less:projects:index` with non-JSON or a non-array, then perform any metadata write. | The entire local library could disappear from the UI and its index could be replaced with an empty/partial list. | **Fixed.** The index now has complete pending/primary/backup generations, validates and repairs rows, deduplicates ids, and reconstructs missing rows by enumerating independent body keys. |
| 2 | Let tab A and tab B load the same body, type different endings, disable `BroadcastChannel`, then autosave A followed by B. | All work in one tab since the two copies diverged—potentially an entire writing session. | **Fixed.** Each tab records the body it opened; a save against an unseen newer body creates a visible `(Recovered conflict)` project instead of choosing a winner. The same guard covers a restore racing another tab's save. |
| 3 | Start cloud save A, type/save B, let B's response arrive first and A's response arrive last. | Every edit between snapshots A and B on other devices; locally B could be clean while the cloud held A. | **Fixed.** A project now has one serialized body-save queue; a queued pass snapshots only after the older response completes. Hook tests hold and release the two responses explicitly. |
| 4 | Fill localStorage so the body safety/pending write throws, then autosave a larger document. | The edits since the last successful autosave (normally seconds; in a long-failing session, all later work). | **Fixed where persistence is possible.** The old primary is never replaced unless a complete new mirror is durable; the failed save returns `false`, fires the visible storage-full path, and retries once after synchronous cleanup. If every storage write remains impossible, the in-memory edit cannot survive a browser crash; the UI continues to report it unsaved rather than lying. |
| 5 | Allow the body write but throw `QuotaExceededError` only for `less:projects:index` while creating or patching a project. | A complete imported/new project could become an unreachable orphan, or content and metadata clocks could disagree. | **Fixed.** The complete pending index is authoritative when the primary index is full, and all metadata mutations report whether a durable generation exists. |
| 6 | Open project A in tab A, project B in tab B, let B overwrite the single `lastOpenedId`, then run quota eviction from B. | The entire local body A that tab A was actively editing; if cloud hydration then failed, A could reopen blank/failed. | **Fixed.** Opened project ids form a monotonic cross-tab protection set, eviction marks `bodyEvicted` durably before deletion, and history is never evicted. A corrupt/unwritable protection set disables eviction in the safe direction. |
| 7 | Delete a project in one tab while another tab is still editing and autosaves afterward. | The editing tab's entire session, plus a deleted cloud row could be accidentally recreated. | **Fixed.** Delete first archives the current body and durably queues the tombstone; the stale editor's next save becomes a new local conflict copy, while cloud sync refuses to push it under the deleted id. |
| 8 | Keep an index row but delete/corrupt its body, then open it so the editor falls back to `EMPTY_*` and autosaves. | The entire project: a blank fallback could replace the cloud or remaining metadata. | **Fixed.** Reads try the complete mirror, primary, previous-body backup, and local history; if none is usable, the row is marked for guarded hydration and is never treated as a legitimate blank document. Completely pre-existing corruption in every copy cannot be mathematically reconstructed, so it is blocked rather than overwritten. |
| 9 | Make `crypto.randomUUID()` return an existing project id, then create/import another project. | The entire pre-existing colliding project's body. | **Fixed.** Id allocation checks both the sanitized index and recoverable body namespace, retries collisions, and has a deterministic unique fallback; corrupt duplicate index rows render once. |
| 10 | Silently truncate the primary body/index during `setItem` (crash/profile corruption simulation). | The last complete document, or the entire library index. | **Fixed going forward.** The newest complete body and index remain mirrored independently, writes are read-verified, and loaders reject malformed candidates and fall through to another complete generation. |
| 11 | Save a new title/status on a device whose clock is hours slow while the cloud clock is hours fast. | A project title or status change (not body text) could be discarded as “older” before it ever synced. | **Fixed.** A persisted dirty flag now outranks wall-clock order and forces the unsynced value to push; clocks only choose between clean values. |
| 12 | Fetch a cloud row whose body `updated_at` is newer but whose `title_at` is older. | The latest project title (not body content). | **Fixed/verified.** Title and status reconcile on their dedicated clocks; a content timestamp cannot make an older title win. |
| 13 | Trigger sign-in reconcile and manual/online reconcile together for the same user. | Duplicate cloud creates and inconsistent metadata finalization; usually duplicated projects rather than destroyed text. | **Fixed.** Concurrent callers share one in-flight reconcile promise per user. |
| 14 | Restore a history item when the local history throttle is active, then immediately decide to undo the restore. | The complete pre-restore draft. | **Fixed.** Destructive replacements force a pre-action version, body transactions also retain the prior body outside the ring, forced ids are unique, and a restore of the old primary creates an undo version of the restored state. |
| 15 | Repeatedly autosave and add forced history entries, or evict a clean cloud-backed body under pressure. | Unbounded history could fill storage; clearing it during eviction could destroy the only old draft. | **Fixed.** The ring remains capped at 8 entries and ~1.2 MB, while eviction retains the ring and only removes a current body that is clean, cloud-confirmed, synced, and never opened in any tab. |
| 16 | Make every localStorage getter/setter throw (private/disabled storage), then create a blank project. | The entire new project could appear saved until reload even though no body or index existed. | **Fixed as detection/containment.** Reads fail closed, creates throw, autosaves return `false`, and partial session writes are not accepted. No browser code can make disabled storage durable, so work remains memory-only until the writer enables storage or sync. |
| 17 | Fail migration's index write, reload, and run legacy migration again with no legacy cloud id. | Duplicate migrated projects and ambiguous copies; the original legacy document itself remained present. | **Fixed.** The migration id is a stable hash of the untouched legacy payload, pending indexes count as complete, writes are recoverable, and all legacy keys remain unchanged for rollback. |
| 18 | Fill storage while saving or clearing a title page. | The entire title page text. | **Fixed.** Title pages now use pending/primary/backup plus an explicit cleared marker, return failure to the caller, and are copied into recovered conflict projects. |
| 19 | Delete locally, then make tombstone persistence or the cloud delete fail. | A deleted project could resurrect from the cloud; no new text was destroyed, but duplicate/stale content returned. | **Fixed.** Tombstones have recoverable generations, are written before index/body removal, are cleared only after confirmed cloud deletion, and failed safety writes leave the live local project untouched. |

## Cloud failure scenarios verified without a new loss finding

- A mid-flight **401** leaves the session and every local cloud-backed body in place, keeps the document dirty, and reports an error until re-authentication.
- A **500** throws through the cloud client, leaves the body dirty/local, and does not advance `lastSavedAt`.
- A hung request is aborted after **20 seconds** and rejects as a timeout instead of leaving sync permanently stuck.
- A fetch or save response arriving **after editor unmount** cannot replace editor content, clear dirty state, or advance the saved clock.
- Content reconcile remains local-first under clock skew; a dirty local body pushes regardless of either wall clock.
